# ADR-001: IDL для программы `clench` пишется вручную, не генерируется `anchor build`

## Статус

Принято (Фаза 2, 2026-09-13).

## Контекст

`anchor build`/`anchor idl build` компилирует `anchor-syn` 0.30.1 на хост-машине
(не в BPF-таргет) для извлечения IDL из макросов. В этом окружении (Rust/cargo
2026 года) это упирается в цепочку несовместимостей:

1. Современный `proc-macro2` убрал `Span::source_file()`, которым пользуется
   `anchor-syn` 0.30.1 напрямую.
2. Достаточно старый `proc-macro2`, где метод ещё есть, использует nightly-путь
   через `proc_macro::Span::source_file()`/`proc_macro::SourceFile` — эти API
   тоже убраны из современного `rustc`.
3. Подбор промежуточной версии `rustc` (1.85.0) упирается в MSRV транзитивных
   proc-macro-крейтов (`jobserver`, `rayon`, `unicode-segmentation` требуют
   ≥1.85) versus API, убранные к этой версии (`proc-macro-error` не собирается
   из-за отсутствующего `From<proc_macro::Span> for proc_macro2::Span`).
4. Попытка закрепить более старые версии транзитивных крейтов (`indexmap`,
   `proc-macro-crate`, `toml_edit`…) заново упирается в `edition2024`,
   которую они требуют, а старый `cargo` не умеет парсить.

Итог: нет версии host-тулчейна, на которой одновременно собираются
*все* транзитивные зависимости `anchor-syn`'s idl-build пути в этом окружении
на момент Фазы 2. Сама BPF-компиляция программы (`cargo-build-sbf`,
platform-tools) в это не упирается — собирается чисто с зафиксированными
версиями `digest`/`blake3`/`zeroize` в `programs/clench/Cargo.toml` (см.
комментарии там же).

## Решение

IDL для `clench` — **артефакт, поддерживаемый вручную**: `program/idl/clench.json`,
скопированный в `target/idl/clench.json` перед `anchor test` (см. `[scripts] test`
в `Anchor.toml`). Дискриминаторы инструкций/аккаунтов — `sha256("global:<snake_case>")`
/ `sha256("account:<PascalCase>")`, первые 8 байт — вычислены и не меняются, пока
не меняются имена инструкций/аккаунтов в Rust.

## Последствия

- **При добавлении/изменении инструкции или аккаунта** — `program/idl/clench.json`
  нужно обновить вручную (добавить/поправить `accounts`/`args`/`types`,
  пересчитать дискриминатор при переименовании).
- **Перед аудитом (Фаза 6) и продакшен-сборкой** — стоит выделить время на
  решение этой проблемы системно: обновить весь стек до Anchor, у которого
  `idl-build` чинен под современный `rustc` (Anchor к 2026 году ушёл на
  major-версии 1.x — миграция сама по себе отдельная задача), либо зафиксировать
  для CI/verifiable-сборок конкретный старый Docker-образ с тулчейном
  соответствующей anchor 0.30.1 эпохи (стандартная практика `anchor build --verifiable`).
- До тех пор — риск человеческой ошибки при ручной правке IDL. Смягчается тем,
  что несовпадение IDL с реальным бинарником проявляется быстро и явно
  (`AnchorError`/`InstructionDidNotDeserialize` при первом же вызове), а не тихо.
